# 预设制作约定

每份预设都应能回答：参数从哪里来、会改动什么、适合哪类素材、验证到了哪一步。

## 参数依据

`presets/confirmed/` 保存有明确数值依据的复现版。来源可以是用户给定参数、原作者公开预设或教程面板。记录原始链接、时间点和最终数值，不能把中间步骤当作最终值。

`presets/partial/` 保存资料不全的简版。名称和说明要指出缺少的部分，未确定的数值保持缺省。

后续按作品近似制作的预设放入 `presets/studies/`，在名称中标明「风格研究」。其中的数值属于本项目试验，不能归为摄影师原始配方。当前尚未生成这一类预设。

## 文件与修改

- 每份 XMP 配套 `.source.json` 和 `.verification.json`，分别记录依据与验证结果。
- 保留用户指定数值，不改未指定设置；缺省与写入零值含义不同。
- 需要适配其他场景时新增变体，使用不同文件名和 UUID，说明改动原因。
- 曲线需记录每个锚点；估算值要标明估算，不能写成读到的数值。
- 曝光、白平衡和相机配置文件是否固定，必须在说明中写清楚。RAW 与 JPEG／HEIC 分别验证。
- 不覆盖已有同名文件。已经发布的版本有误时，保留可追溯的修订记录。

## 检查与实测

文件检查包括 XML 语法、RDF 结构、字段和值、曲线锚点、UUID 唯一性及 SHA-256。核对时检查有无遗漏字段，也检查有无多写字段。

Lightroom 实测需记录应用版本和素材类型。在测试副本或虚拟副本上导入预设，确认面板可见，再应用并读回参数。文件检查与软件实测分别记录，未做的步骤保持 `false` 或写明未验证。

安装前先确认 Lightroom 实际使用的目录，也要检查是否启用随目录保存预设。若需要重启 Lightroom，先征得同意。原始照片和现有预设保持完整。

## 后续作品研究

先限定摄影师的具体系列、光线和拍摄场景，再确定仿色目标。资料优先采用本人网站、基金会、美术馆和摄影机构的作品页或访谈，保留直接链接。

每次试验同时记录适用照片与失败案例。色调调整、构图、现场光线和景深分别分析，避免用一份全局预设承诺整个摄影师的风格。

研究阶段不上传第三方原图或视频。公开对照样张前确认使用权限，清除不必要的定位与个人信息。
